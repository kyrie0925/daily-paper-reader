## 摘要
微服务系统广泛用于构建云应用，但其复杂性使得故障不可避免，从而降低用户体验并造成经济损失。自动化的异常检测与根因分析（RCA）已成为活跃的研究领域，但现有技术存在五个局限。首先，大多数方法将异常检测与根因分析分开处理，假设异常能被正确检测，而当检测因噪声或延迟而不精确时便会失效。其次，它们主要关注指标、日志和追踪，而对API调用、配置变更等事件数据探索不足。第三，许多方法需要给定的服务调用图，缺乏此图则无法进行诊断。第四，该领域缺乏标准化的数据集和评估框架，因此方法难以公平比较。第五，尽管基于因果推断的根因分析已成为主流，但其有效性、效率和鲁棒性仍不明确。

本文通过两组贡献解决了这些局限。第一组引入了独立和联合利用可观测性数据的方法。BARO是一种针对指标数据的端到端异常检测与根因分析方法。EventADL是一种针对事件数据的端到端框架。TORAI是一种无需服务调用图的多模态根因分析框架。在真实微服务系统上的大量实验证明了它们的有效性和鲁棒性。第二组提供了基准数据集、评估框架和系统性的评估工作。RCAEval是一个综合基准，为未来研究提供即用数据集和可复现基线。对现有根因分析方法（尤其是基于因果推断的方法）的系统性评估提供了指导未来方向的见解。本文从而推动了微服务故障的自动化异常检测与根因分析，支持未来关于事件缓解与修复的研究。

## Abstract
Microservice systems are widely used to build cloud applications, yet their complexity makes failures inevitable, degrading user experience and causing economic loss. Automated anomaly detection and root cause analysis (RCA) are now active research areas, but existing techniques share five limitations. First, most treat anomaly detection and RCA separately, assuming anomalies are detected correctly, and falter when detection is imprecise due to noise or delay. Second, they focus on metrics, logs, and traces, leaving event data such as API calls and configuration changes underexplored. Third, many require a given service call graph and cannot diagnose without one. Fourth, the field lacks standardised datasets and evaluation frameworks, so methods are hard to compare fairly. Fifth, although causal inference-based RCA has become dominant, its effectiveness, efficiency, and robustness remain unclear.   This thesis addresses these limitations through two groups of contributions. The first introduces methods that exploit observability data both independently and collectively. BARO is an end-to-end anomaly detection and RCA approach for metric data. EventADL is an end-to-end framework for event data. TORAI is a multimodal RCA framework that requires no service call graph. Extensive experiments on real microservice systems demonstrate their effectiveness and robustness. The second group delivers benchmarking datasets, an evaluation framework, and systematic evaluation efforts. RCAEval is a comprehensive benchmark providing ready-to-use datasets and reproducible baselines for future research. A systematic evaluation of existing RCA methods, especially causal inference-based approaches, offers insights that guide future directions. This thesis thereby advances automated anomaly detection and RCA for microservice failures, enabling future research on incident mitigation and remediation.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：微服务架构已成为云应用的标准，其复杂性导致故障频发。一次停机可能造成巨大经济损失（如亚马逊一小时停机损失可达1亿美元），甚至危及生命。人工监控和分析不可行，因此需要自动化的异常检测与根因分析（RCA）。
- **现有局限**：已有工作存在五大关键不足：
  1. 异常检测与RCA解耦，假设检测完美，实际中不精确检测会严重降低RCA性能。
  2. 过度依赖指标、日志和追踪，忽视事件数据（如API调用、配置变更）的潜力。
  3. 许多多源RCA方法要求完整的服务调用图（由追踪构建），但实际系统中存在盲点（无追踪的服务），导致方法失效。
  4. 缺乏标准化基准（数据集、评估协议），导致方法难以公平比较。
  5. 基于因果推断的RCA方法的效果、效率和鲁棒性缺乏系统评估。
- **研究目标**：开发能够利用多模态可观测性数据（指标、事件、日志、追踪）的自动化异常检测与RCA方法，并提供标准化基准和系统性评估，推动该领域发展。

## 2. 方法论：核心思想、关键技术细节

### 2.1 贡献组一：新方法

#### BARO（第3章）：基于指标的端到端异常检测与RCA

- **核心思想**：将异常检测与RCA紧密结合，使用多元贝叶斯在线变点检测（Multivariate BOCPD）进行异常检测，并提出鲁棒评分器（RobustScorer）进行RCA，对检测时间的不精确具有鲁棒性。
- **关键技术**：
  - **Multivariate BOCPD**：建模多元时间序列的依赖关系，通过计算游程长度（run length）的后验概率来检测变点（异常）。使用多元高斯和逆Wishart先验计算边缘似然。
  - **RobustScorer**：使用**中位数（median）和四分位距（IQR）**而非均值和标准差进行假设检验，计算每个指标在异常期间的最大偏离程度作为根因得分，对检测时间偏差具有鲁棒性。
- **流程**：指标数据 → Multivariate BOCPD检测异常 → 若检测到，调用RobustScorer计算各指标得分 → 输出根因服务的排序列表。

#### EventADL（第4章）：基于事件的白盒异常检测与根因定位

- **核心思想**：基于对520个真实事件的分析，提出通过事件语义模式（ESP）和事件频率模式（EFP）进行可解释的异常检测，并构建干预图（Intervention Graph）进行根因定位。
- **关键技术**：
  - **ESP**：从历史事件中学习规则（如使用HyGLAD），用于检测点异常（异常事件类型或值）。
  - **EFP**：对每个ESP的频率时间序列，使用矩阵剖面（Matrix Profile）风格的子序列距离，并用假设检验检测频率异常。
  - **干预图**：根据事件中的actor、操作、资源构建有向图，然后使用**时间感知随机游走**（Time-Aware Random Walk）回溯到根因事件。
- **优势**：全白盒，可解释，能检测点异常和频率异常，具备自适应机制。

#### TORAI（第5章）：无需服务调用图的多模态RCA

- **核心思想**：解决现有方法依赖完整调用图的局限。通过严重性评分、症状聚类、因果分析和假设检验的组合，在存在盲点（无追踪服务）时也能有效定位根因。
- **关键技术**：
  - **SeverityScorer**：对每个服务的每个数据源（指标、日志、追踪）计算异常严重性得分，生成严重性向量。
  - **SymptomCluster**：使用高斯混合模型（GMM）对服务进行聚类，将异常服务与正常服务分开。
  - **CausalRanker**：在每个聚类内使用Ψ-PC算法进行因果发现，识别根因服务。
  - **RankAggregation**：按聚类级别和内部因果排名聚合得到粗粒度根因服务排序。
  - **FineGrainer**：使用中位数和IQR的假设检验，从根因服务中找出细粒度根因指标（如具体度量、日志模板）。
- **流程**：多模态数据 → 转换时间序列 → 严重性评分 → 症状聚类 → 聚类内因果排名 → 聚合排序 → 细粒度根因定位。

### 2.2 贡献组二：基准与评估

#### RCAEval（第6章）：标准基准

- 提供三个数据集（RE1、RE2、RE3），共735个故障案例，覆盖11种故障类型（资源、网络、代码级）。
- 包含15个可复现的基线方法（基于指标、追踪、多源的RCA），支持粗粒度和细粒度评估。
- 数据来自三个广泛使用的微服务系统（Online Boutique、Sock Shop、Train Ticket）。

#### 因果推断RCA方法系统评估（第7章）

- 评估9种因果发现方法和21种RCA方法，在6个合成数据集和4个真实系统数据集上进行。
- 考察因果图构建效果、RCA定位效果、效率、输入数据长度影响、超参数调优、故障时间误指定等因素。

## 3. 实验设计

### 数据集

- **真实系统**：Online Boutique（12服务）、Sock Shop（11-15服务）、Train Ticket（64服务）。在Kubernetes集群上部署，使用Istio、Prometheus、cAdvisor收集指标；Vector/Loki收集日志；Jaeger收集追踪。
- **合成数据集**：来自CIRCA、RCD、CausIL三种生成器，生成10/50节点规模的系统。
- **真实世界事件**：520个来自AWS的事故报告，以及两个真实事件（OUT、AVA）。
- **故障类型**：CPU过载、内存泄漏、磁盘IO、Socket压力、网络延迟、丢包、代码级缺陷（如参数错误、异常处理缺失）。

### 对比方法

- **BARO对比**：N-Sigma、SPOT、BIRCH、UniBCP（异常检测）；CausalRCA、RCD、CIRCA、ϵ-Diagnosis、N-Sigma（RCA）。
- **EventADL对比**：14种异常检测方法（如DeepSVDD、DIF、NeuralLog、ShadeWatcher等）；10种RCA方法（如BARO、CausalRCA、DeepHunt、KPIRoot等）。
- **TORAI对比**：9种基线（如BARO、RCD、CIRCA、PDiagnose、HeMiRCA等）。
- **因果评估**：9种因果发现算法（PC、FCI、Granger、LiNGAM、GES、PCMCI等）；21种RCA方法（包括PC-PageRank、CausalRCA、RCD、CIRCA、BARO等）。

### 评估指标

- 异常检测：Precision、Recall、F1-score。
- RCA（粗粒度/细粒度）：AC@k（k=1,3,5）和Avg@5。

## 4. 资源与算力

- **论文未明确说明GPU型号和数量**。实验主要在Linux服务器上运行，文中提到“8 CPU, 16GB RAM”的机器用于部分实验。EventADL的扩展性实验使用了12 vCPU, 36GB RAM的机器。因果评估部分提到总运行时间超过400小时（单次重复），但未提供GPU信息。因此，**未详细报告GPU算力需求**。

## 5. 实验数量与充分性

- **BARO**：3个真实系统 × 100个案例 × 5次重复 → 500+次实验。进行RCA敏感性分析（参数、偏差时间、超参数）。
- **EventADL**：3个真实系统（各30个测试样本）+ 2个真实事件数据集，14种基线，10次重复。包含消融实验（ESP vs EFP、shape-based vs magnitude-based、HyGLAD vs Drain）、鲁棒性分析（噪声、参数变化）。额外在3个公共基准（Eadro、GAIA、AIOps21）上测试EFP泛化性。
- **TORAI**：3个系统 × 90案例 + 10个真实事件，9种基线，5次重复。包含消融实验（单个组件贡献）、盲点敏感性分析（0%-100%缺失追踪）。
- **因果评估**：6个合成数据集 + 4个真实系统数据集，多种故障类型，多种数据长度（60-600点），重复5次。总实验量极大（>400小时单次重复）。
- **结论**：实验覆盖广泛，多种故障、多数据集、多基线、统计显著性检验（t-test）。消融和鲁棒性分析充分，公平性较好。但合成数据集和真实系统结果存在不一致，提示需谨慎解读。

## 6. 主要结论与发现

1. **BARO**：在异常检测（F1最高0.82/0.75/0.81）和RCA（粗粒度Avg@5最高0.86/0.95/0.81）上一致优于所有基线，且对检测时间偏差最鲁棒。
2. **EventADL**：异常检测F1≥0.90，根因定位AC@3达100%，在所有数据集上大幅优于现有方法。EFP可泛化到非事件数据（公共基准F1达89.9%-92.3%）。
3. **TORAI**：在存在盲点（特别是Sock Shop无追踪）时仍能达到粗粒度Avg@5≥0.83，显著优于依赖调用图的基线。在真实事件上AC@3=100%。
4. **因果RCA评估**：
   - 无方法在所有情况下最优；直接应用因果发现（PC、FCI等）+ PageRank/随机游走的方法效果几乎等于随机选择。
   - 合成数据集结果不能真实反映真实系统表现。
   - 数据长度增加可提升部分方法（RCD、CausalRCA、BARO、CIRCA）性能。
   - 故障时间误指定对CIRCA、N-Sigma影响大，BARO相对鲁棒。
5. **RCAEval**：提供标准化基准，初步实验显示现有方法仍有很大提升空间（如Train Ticket上最佳Avg@5仅0.81）。

## 7. 优点

- **方法创新**：提出的三个方法分别解决了现有工作中的关键盲点（检测-RCA耦合、事件数据利用、免调用图）。BARO的RobustScorer（中位数+IQR）在理论上具有鲁棒性；EventADL的白盒设计增强了可解释性和可信度；TORAI的聚类+因果+假设检验组合有效且高效。
- **实验严谨**：多个真实系统、大量故障类型、多次重复、统计检验、消融实验、鲁棒性分析、参数敏感性分析。覆盖了多种实验条件（不同数据长度、噪声水平、盲点比例）。
- **实际价值**：方法均基于无监督学习，无需标签数据；数据收集成本低（指标/日志易获取）；在真实事件中得到验证。
- **基准贡献**：RCAEval填补了标准化基准的空白，提供即用数据集和可复现基线，降低未来研究门槛。
- **因果评估**：首次全面系统地评估了9种因果发现算法和21种RCA方法，揭示了众多实用洞察，为后续研究提供方向。

## 8. 不足与局限

- **系统规模**：主要实验在单节点Kubernetes集群上进行，最大系统64个服务，未验证在超大型（数千服务）生产环境中的扩展性。
- **故障覆盖**：虽然覆盖了常见资源/网络/代码级故障，但某些故障类型（如安全攻击、配置错误、依赖服务故障）未被深入评估。
- **盲点假设**：TORAI假设盲点服务仍可收集指标和日志，但若盲点完全无法收集任何数据，方法失效。
- **因果评估局限**：因果发现方法在大型图上效果差，可能受到数据集限制；未评估最新大模型或图神经网络方法。
- **泛化性**：所有方法针对微服务系统设计，推广到其他分布式系统（如数据库、大数据平台）需进一步验证。
- **算力资源未详述**：未明确给出GPU信息，读者难以判断计算成本。
- **黑盒组件**：EventADL使用HyGLAD提取ESP，HyGLAD本身是外部工具，其错误可能传播。但消融实验显示使用Drain取代仍表现良好，表明框架不依赖特定工具。
- **人为假设**：BARO假设故障首先影响延迟或错误指标；TORAI假设根因服务有不同症状（聚类前提）。这些假设在部分场景可能不成立。
